Event listeners survive morphing

The morph engine moves/patches nodes instead of replacing them — the node keeps its identity, so both native addEventListener listeners and delegated handlers (df$.registerDelegatedEvent) keep working after the morph.

Native listener: node created → text morphed → still clickable

Open the console: the node identity check proves the same element survives.

Delegated handler: survives repeated morphs, never double-fires

Cleanup: removing a node removes its handlers

The registry entry is cleared during the morph — the synthetic click does nothing.
