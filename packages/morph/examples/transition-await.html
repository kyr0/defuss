Transitions: content is latest-wins, await sequences animations

morph() with a transition returns a Promise that resolves when the transition completed. Overlapping updates are latest-wins: a plain morph issued while a transition is in flight applies immediately and also replaces the transition's pending content — the transition finishes with the newest HTML, never stale content. What you still control is animation sequencing: await (or a queue) plays transitions one after another.

The patterns

// latest-wins: the plain morph during the exit phase rewrites the
// transition's pending content — the final DOM shows C, with the
// transition animation completing around it
const pending = morph(el, htmlB, { transition: { type: "slide-left" } });
morph(el, htmlC);
await pending; // content: C ✓
// sequential animations: await the transition before the next morph
await morph(el, htmlB, { transition: { type: "slide-left" } });
morph(el, htmlC);
// rapid-fire updates: a tiny morph queue
let chain = Promise.resolve();
const queueMorph = (html) => (chain = chain.then(() =>
  morph(el, html, { transition: { type: "slide-left", duration: 150 } })));
queueMorph(htmlB);
queueMorph(htmlC); // every update plays out in order
